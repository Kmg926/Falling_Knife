# 로컬 ComfyUI를 시험했지만 그림은 계속 코드로 만든다

ADR 0003에서 Comfy Cloud를 쓰지 않은 이유는 유료 구독이었다. 2026-11-18 사용자 컴퓨터(RTX 4070 SUPER 12GB)에 **로컬 ComfyUI**(무료)를 설치해, 큰 한 장짜리 그림(타이틀 배경)에서 코드 그림보다 나은지 시험했다(comfy-local Grilling Q1~Q9, Ticket 50·51). 사용자 기준은 "Comfy를 쓰는 게 **퀄리티가 더 높아지고 편하면** 계속"이었고, 4번 시험한 결과 두 조건 모두 맞지 않아 **채택하지 않는다**. 그림은 ADR 0003대로 AI가 코드(`tools/`)로 만든다. 로컬 ComfyUI는 설치된 채로 두고(모델 파일은 저장소 밖), 필요하면 아이디어 스케치에만 쓸 수 있다.

## 시험 (Ticket 51, SDXL base 1.0 + pixel-art-xl LoRA + 고친 VAE, 생성 1장 약 7초)

| 차 | 방법 | 결과 |
|---|---|---|
| 1 | 글 프롬프트(어두운 도박장·전등·떨어지는 차트·왼쪽 비움) | 너무 밝고 물건이 많음, 차트 없음, 왼쪽이 안 빔 |
| 2 | 프롬프트 강화(아주 어둡게·장식 빼기) | 더 나빠짐: 바탕이 회색·흰색, 차트가 올라감 |
| 3 | 코드로 그린 구도 밑그림(그라데이션) → img2img 0.6, 차트는 빼고 배경만(사용자: 움직이는 선은 게임 코드가 맡음) | 구도는 맞음, 하지만 우리 그림과 스타일이 너무 다름(사용자 지적) |
| 4 | **우리 게임 스프라이트(방·테이블·전등·빛줄기)+조명 흉내**를 640 격자 정확히 2배로 합성 → img2img 0.35·0.5 | 처음으로 우리 그림과 같은 모양·색. 하지만 Comfy가 더한 것은 바닥 얼룩·작은 물건 정도, 오히려 깔끔함이 줄어듦 |

재현: 워크플로 `tools/comfy/title-bg*.json`, 생성 `tools/comfy_generate.py`(같은 시드 → 같은 픽셀 확인, C2), 후처리 `tools/comfy_postprocess.py`(32색·640 격자, C3), 밑그림 `tools/comfy_sketch.py`. 비교 그림 `.scratch/art/drafts/comfy/post/sheet-v1~v4.png`.

## 왜 안 맞았나

- 이 게임 그림은 **640 격자의 가는 도트 + 32색 + 정해진 원근**이다. 도트 LoRA는 8배 굵은 도트로 그려서 줄이면 뭉개지고, 글 프롬프트는 우리 팔레트·원근을 모른다.
- 우리 그림을 밑그림으로 주면 스타일은 맞지만, 바꾸는 양을 줄일수록 Comfy가 더하는 것이 없다. **스타일이 맞을수록 이득이 사라지는** 구조.
- 편함: 매번 밑그림·후처리·팔레트 맞추기가 필요해, 코드로 바로 그리는 것보다 단계가 많다.

## Considered Options

- **스타일 참조(IP-Adapter) / 우리 그림으로 LoRA 학습:** 추가 노드·모델(약 3GB) 설치나 학습 시간이 들고, 640 도트 스타일을 지킬지 확실하지 않음 → 지금 일정에선 하지 않음.
- **4차 결과를 그대로 쓰기:** 우리 그림보다 나아진 점이 없어 쓰지 않음.

## Consequences

- 그림·효과음은 계속 AI가 코드로(ADR 0003, gdd-changes #36~38·#42). gdd-changes #67은 "시험 → 채택 안 함"으로 닫는다.
- 타이틀 배경은 코드로: 4차 밑그림(`tools/comfy/title-bg-ours.png`, 우리 스프라이트 합성)이 후보. 움직이는 차트 선도 게임 코드로(사용자 결정). 둘은 따로 할 일.
- 라이선스(SDXL CreativeML Open RAIL++-M, pixel-art-xl CreativeML Open RAIL-M, 고친 VAE MIT): 게임에 들어간 생성 그림이 없으므로 `asset-rights.md`에 넣을 줄 없음. 모델 파일은 저장소에 없음(재배포 의무 없음).
