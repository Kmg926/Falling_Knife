# Grilling: 광대 행동 (광대 AI)

> 2026-11-09. 지금은 광대 차례도 사람이 누르는 핫시트. 광대가 스스로 행동하게 만든다.
> 질문은 AI가 추천 답과 함께 묻고, 사용자가 채택·거절했다. 2라운드, Q1~Q14 **모두 채택**.

## 확인한 사실 (질문 전)
- GDD 광대 AI: ① 차트 분석 있으면 사용→결과대로 ② 거래 정지 사용 ③ 잔고 1이면 복권 ④ 그 외 남은 덱 하락 비율 50% 이상이면 매도·찌라시, 미만이면 보유
- 아이템이 아직 없어서 ①~③과 ④의 찌라시는 쓸 수 없다.
- 지금 코드: 차례가 광대로 넘어가도 플레이어 입력(A/D·Space)이 광대 행동을 대신한다.

## 1라운드
| Q | 질문 | 추천 = 결정 | 이유 |
|---|---|---|---|
| Q1 | 범위 | 덱 비율 규칙(④)만. 아이템 규칙은 아이템 구현 때 추가 | 아이템 없이 쓸 수 있는 규칙은 ④뿐. gdd-changes "임시" |
| Q2 | 비율 계산 | 남은 하락 ÷ (남은 하락 + 남은 상승) ≥ 0.5 → 매도, 미만 → 보유. 정확히 50%면 매도. 광대는 남은 개수만 알고 다음 캔들은 모름 | GDD "50% 이상" 그대로 |
| Q3 | 보유+상승 뒤 | 광대가 같은 규칙으로 다시 고른다 | 사람과 같은 턴 규칙(턴 유지) |
| Q4 | 생각 시간 | 고르기 전 `광대 생각 중...` 0.5초, Inspector 숫자 칸 | 없으면 광대 턴이 너무 빨라 무슨 일인지 안 보임. 경험 확인 때 조정 |
| Q5 | 광대 차례 입력 | A/D·Space 무시. R은 지금처럼 끝난 화면에서만 | GDD "광대 턴엔 입력 무시" |
| Q6 | 구조 | `ClownAI.cs` = 판단 함수 하나(남은 하락·상승 수 → 보유/매도). GameManager가 차례가 오면 묻고, 기다리고, 기존 공개 처리를 씀 | GDD 구현 계획의 ClownAI. 판정은 GameManager 한 곳 → 면담 설명 쉬움 |
| Q7 | 화면 | 생각 중엔 `광대 생각 중...`, 그다음 `선택:` 줄에 광대 선택, 결과는 기존 문구 | 광대가 무엇을 골랐는지 보이게 |
| Q8 | 핫시트 체크칸 | 남기지 않음 | 고정 순서 + 정해진 규칙으로 재현 가능. 분기 하나 줄임. 테스트 표는 새로 씀 |

## 2라운드
| Q | 질문 | 추천 = 결정 | 이유 |
|---|---|---|---|
| Q9 | 광대 턴 도중 라운드 종료 | 매 행동 전 "라운드 끝났나?" 확인, 끝났으면 멈추고 끝난 화면(패배·클리어·최종 승리) | 끝난 뒤 광대가 계속 뽑으면 안 됨 |
| Q10 | 광대 턴에 재장전 | 처리 순서(피해 → 파산 → 재장전) 그대로. 마지막이 광대 보유+상승이면 광대가 새 덱 비율로 계속, 아니면 플레이어 차례 | 기존 차례 규칙 유지 |
| Q11 | Ticket | **09** 내가 턴을 넘기면 광대가 남은 덱 비율로 스스로 보유·매도한다 / **10** 광대 턴에 라운드가 끝나거나 덱이 재장전돼도 맞게 이어진다 | 09만으로 "광대와 대전"이 됨. 10은 경계 상황 확인 |
| Q12 | 테스트 | ① MCP로 판단 함수에 숫자 넣기: 2/3→보유, 2/2→매도, 3/1→매도, 0/4→보유 ② 고정 순서 + 키 → 화면 글자, 표에 광대 행동까지 미리 적음 | 판단과 흐름을 따로 확인 |
| Q13 | 경험 확인 | 광대가 "상대"처럼 느껴지는가 / 광대 턴 속도(생각 0.5 + 공개 0.5)가 적당한가 | 숫자 조정은 한 번에 하나 |
| Q14 | 기록 | `.scratch/clown-ai/`, gdd-changes 두 줄(임시: 아이템 규칙 없음 / 구체화: 생각 0.5초) | GDD 제출본 수정 불가 |
