Status: ready-for-agent

> 근거: 2026-11-09 Grilling Q1~Q14 (모두 사용자 채택, 질문·이유는 `grilling.md`). 기존 기능: `../three-rounds/` (3라운드 진행, 커밋 `cc6fff4`).
> 정상 버전(수정 전): 이 Spec·Ticket 커밋.
> Spec 작성 중 AI가 제안한 세부 2개(static 함수, 생각 중 문구 덧붙이기)는 2026-11-09 사용자가 **둘 다 채택**.

## 변경·유지·확인

**변경:** 광대 차례를 사람이 대신 누르던 핫시트를 없앤다. 차례가 광대로 넘어가면 광대가 `광대 생각 중...`(0.5초) 뒤 남은 덱의 하락 비율로 보유·매도를 스스로 고르고, 기존 공개·판정을 그대로 탄다.

**유지 (이유):**
- U1 플레이어 차례는 지금과 똑같다: A/D 선택, Space 실행, 공개 0.5초, 결과 문구 (이미 검증한 동작)
- U2 처리 순서 피해 → 파산 판정 → 재장전 (GDD 처리 순서). 광대 행동도 같은 공개·판정 코드를 쓴다
- U3 3라운드 흐름: 클리어 → Space 다음 라운드, 최종 승리, 패배 → R 1라운드, 라운드는 항상 플레이어 차례로 시작 (`three-rounds` C1~C9)
- U4 공개 중 모든 입력 무시, 플레이·공개 중 R 무시 (실수 입력 방지)
- U5 잔고 0 아래로 안 내려감, 레버리지 0~3 (기존 규칙)

**확인 – 작동 (Play 모드, 행동 → 예상 결과):**
- C1 판단 함수: 남은 하락/상승 2/3 → 보유, 2/2 → 매도, 3/1 → 매도, 0/4 → 보유, 4/0 → 매도 (MCP로 함수 직접 호출)
- C2 내가 매도(또는 보유+하락)로 차례를 넘김 → 내 결과 문구가 남은 채 `광대 생각 중...` → 0.5초 뒤 `선택:` 줄에 광대 선택 → `공개 중...` → 광대 결과 문구
- C3 광대 생각 중·공개 중 A/D·Space·R → 변화 없음 (선택 줄도 안 바뀜)
- C4 광대가 보유 → 상승이면 광대가 다시 생각하고 고른다 (하락이 나오거나 매도할 때까지)
- C5 광대 턴이 끝나면 `차례: 플레이어`, `[보유]`, 다시 내 입력이 먹힌다
- C6 광대가 매도 → 하락으로 내가 파산 → `패배... - R로 처음부터`, 광대는 더 고르지 않음
- C7 광대가 보유 → 하락으로 스스로 파산 → `라운드 N 클리어!`(3라운드면 `최종 승리!`), Space(클리어)·R이 그대로 동작
- C8 광대 턴에 덱이 바닥나면 `덱 재장전` → 마지막이 광대 보유+상승이었으면 광대가 새 덱 비율로 계속, 아니면 플레이어 차례
- C9 퇴행: 클리어 화면에서 차례가 광대로 표시되어 있어도 Space로 다음 라운드, 다음 라운드는 플레이어 차례로 시작

**확인 – 경험 (직접 플레이):** 광대가 "상대"처럼 느껴지는가(너무 뻔하거나 바보 같지 않은가) / 광대 턴 속도(생각 0.5 + 공개 0.5)가 답답하거나 너무 빠르지 않은가. 숫자 조정은 한 번에 하나.

**확인 전:** 구현 전이라 전부 확인 전.

## Problem Statement

지금은 차례가 광대로 넘어가도 플레이어가 A/D·Space로 광대 행동까지 대신 누른다(핫시트). 그래서 "광대와 대결한다"는 GDD의 핵심 경험을 시험할 수 없고, 한 판 길이(3~5분)나 난이도도 잴 수 없다.

## Solution

광대 차례가 되면 GameManager가 0.5초 기다린 뒤 ClownAI에게 "남은 하락·상승이 이만큼인데 뭘 할래?"를 묻고, 받은 행동(보유/매도)으로 기존 공개·판정을 그대로 실행한다. 광대 차례 동안 플레이어 입력은 무시한다. 판단 규칙은 GDD ④(하락 비율 50% 이상이면 매도, 미만이면 보유)만 쓴다.

## User Stories

1. 플레이어로서, 내가 턴을 넘기면 광대가 스스로 행동하길 원한다. 혼자서도 대결할 수 있도록.
2. 플레이어로서, 광대 차례가 시작되면 `광대 생각 중...`을 보고 싶다. 광대가 행동한다는 걸 알 수 있도록.
3. 플레이어로서, 광대가 생각하는 동안에도 내 직전 결과 문구를 읽고 싶다.
4. 플레이어로서, 광대가 무엇을 골랐는지(`선택:` 줄) 공개 전에 보고 싶다.
5. 플레이어로서, 광대 결과도 내 결과와 같은 문구(`보유 → 하락! 광대 -2` 등)로 보고 싶다.
6. 플레이어로서, 광대 차례에 실수로 누른 키가 아무 영향을 주지 않길 원한다.
7. 플레이어로서, 광대가 보유해서 상승이 나오면 광대가 계속 행동하길 원한다(나와 같은 규칙).
8. 플레이어로서, 광대 턴이 끝나면 바로 내 차례로 돌아오고 선택은 `[보유]`로 시작하길 원한다.
9. 플레이어로서, 광대 행동으로 누가 파산하면 광대가 바로 멈추고 끝난 화면을 보고 싶다.
10. 플레이어로서, 광대가 남은 덱을 보고 그럴듯하게 판단하길 원한다(하락이 많으면 나에게 넘김).
11. 테스터로서, 고정 순서를 쓰면 광대 행동까지 미리 예측해 테스트 표에 적고 싶다.
12. 테스터로서, 판단 규칙을 Play 없이 숫자만 넣어 확인하고 싶다.
13. 개발자로서, 생각 시간을 Inspector 숫자 칸에서 바꾸고 싶다.
14. 개발자(구술 면담 대비)로서, "판단"은 ClownAI, "진행·판정"은 GameManager로 나뉘어 있길 원한다.
15. 개발자로서, 나중에 아이템 규칙(①~③)이나 더 똑똑한 규칙을 ClownAI 한 곳에 덧붙이고 싶다.

## Implementation Decisions

- **ClownAI (판단만):** 남은 하락 수·상승 수를 받아 보유/매도를 돌려주는 함수 하나. 하락 ÷ (하락 + 상승) ≥ 0.5 → 매도, 아니면 보유. 둘 다 0이면 보유(안전장치, 재장전 때문에 실제로는 없음).
  - (AI 제안 → 사용자 채택) Scene에 붙이는 컴포넌트가 아니라 `static` 함수(`ClownAI.Decide(down, up)`). 이유: 상태가 없어 Inspector 연결이 필요 없고, MCP로 바로 호출해 C1을 확인할 수 있다. 생각 시간은 GameManager가 가진다.
- **GameManager (진행·판정):**
  - Inspector `연출`에 `Clown Think Seconds` (기본 0.5) 추가.
  - 상태 추가: "광대 차례 진행 중"(`IsClownTurn` 또는 `Current == Clown`에서 파생)과 "광대 생각 중".
  - 공개가 끝난 뒤 라운드가 안 끝났고 차례가 광대면 → 광대 턴 진행(생각 대기 → ClownAI에게 묻기 → 선택 반영·화면 갱신 → 기존 공개 처리). 공개 뒤 또 광대 차례면(보유+상승) 같은 진행을 반복한다.
  - 매 행동 전 라운드가 끝났으면 멈춘다(Q9). 재장전은 기존 공개 처리 안에서 그대로(Q10).
  - **입력 무시 위치 주의:** `Execute()`는 "공개 중 → 무시", "라운드 클리어 → 다음 라운드", "라운드 끝 → 무시" **다음에** "광대 차례 → 무시"를 둔다. 클리어 화면에서 `Current`가 광대일 수 있기 때문(내 매도로 광대가 파산하면 차례가 광대로 넘어간 상태). `Select()`도 광대 차례면 무시. `Restart()`는 그대로(끝난 화면에서만).
  - `PassTurn()`의 "핫시트" 주석은 고친다.
- **UIManager:** 광대가 생각 중이면 결과 줄 아래 `광대 생각 중...` 한 줄.
  - (AI 제안 → 사용자 채택) `공개 중...`처럼 결과 줄을 **덮지 않고** 덧붙인다. 덮으면 내 직전 결과(예: `매도 → 하락! 광대 -1`)를 볼 틈이 없다(공개가 끝나자마자 광대가 생각을 시작하므로).
- **입력·Scene:** Input Actions 그대로. `PlayerInputHandler`는 동작 변경 없음(무시는 GameManager가 판단), "핫시트" 주석만 고친다. Scene은 GameManager Inspector 값 하나만 생김.
- **Ticket 순서 (Q11):** 09 광대가 스스로 보유·매도(C1~C5) → 10 광대 턴의 라운드 종료·재장전·퇴행(C6~C9).

## Testing Decisions

- **좋은 테스트:** 바깥 동작만 본다. "고정 순서 + 키 입력 → 화면 글자".
- **seam 2개:** ① `ClownAI.Decide(down, up)` 결과(C1, MCP 함수 호출) ② 기존 seam(라운드 표 고정 순서 + 키 → UI 텍스트). 광대 행동은 규칙으로 정해지므로 테스트 표에 **광대가 할 행동까지** 미리 적는다.
- **방법:** C1~C9 수동 체크리스트 + AI가 MCP로 Play·Console·캡처. 테스트 전에 컴파일 시각 > 스크립트 저장 시각 확인(three-rounds 08 교훈). 경험은 직접 플레이. 자동 테스트는 하지 않음.
- **선례:** `three-rounds` issues 06~08 테스트 표.
