# Ticket 08 초안: 어느 라운드에서든 지면 R로 1라운드부터 다시 한다

> **초안**이다(Assets 밖). **직접 타이핑**해서 반영한다(CLAUDE.md 4장). 반영 후 AI는 리뷰만 한다.
> 3라운드 진행의 마지막 Ticket. 근거: `../../spec.md`(C6·C7·C8, Q7·Q9)

## 1. 바꿀 것: `UIManager.cs` 한 줄

지울 줄:
```csharp
            message += "\n패배... - R로 재시작";
```
넣을 줄:
```csharp
            message += "\n패배... - R로 처음부터";
```

**다른 파일은 바꾸지 않는다.** 전문은 같은 폴더의 `UIManager.cs`.

## 2. 왜 이것뿐인가 (코드에서 확인한 사실)

| 08 수락 기준 | 이미 들어 있는 곳 |
|---|---|
| 패배 화면에서 Space·A/D 무시 | `Select()`: `IsRevealing \|\| IsRoundOver`면 무시 / `Execute()`: 클리어가 아니면서 `IsRoundOver`면 무시 (07) |
| 패배·클리어·최종 승리 화면에서 R → 1라운드 | `Restart()`: `IsRoundOver`면 `RoundNumber = 1` → `StartRound()` (06) |
| 플레이·공개 중 R 무시 | `Restart()`: `IsRevealing \|\| !IsRoundOver`면 무시 (05·06) |

- `IsRoundOver`는 플레이어 파산·광대 파산을 모두 포함한다. 그래서 2·3라운드 패배도 같은 길을 탄다.
- 06에서 `Restart()`에 `RoundNumber = 1;`을 미리 넣어 둔 덕분에 동작 코드는 바꿀 게 없다. 남은 건 **화면 문구**를 Spec(Q7)대로 "처음부터"로 맞추는 것뿐이다.
- 08은 "**이미 되는 동작을 2·3라운드에서 확인**"하는 Ticket이다.

## 4. 수동 테스트 (Ticket 08)

> 2라운드 패배를 빠르게 만들려면 고정 순서를 쓴다. 공개 시간은 이제 0.5초.

| # | 고정 순서 | 입력 | 기대 |
|---|---|---|---|
| T53 | E0 `D U U D U`, E1 `U U U D D D U` | 1라운드: D·Space ×3 → Space(클리어) → Space(2라운드) → Space ×3(보유 상승 3번, 레버리지 3) → Space(보유+하락) | `보유 → 하락! 플레이어 -4`, 잔고 0, `패배... - R로 처음부터` (C6) |
| T54 | 이어서 | Space, A, D | 변화 없음 |
| T55 | 이어서 | R | `라운드 1 / 3`, 잔고 2/2, 남은 2/3, 플레이어 차례 (C6) |

| T57 | (07 고정 순서로 3라운드까지) | 최종 승리 화면에서 R | `라운드 1 / 3` |
