## Problem Statement

마일스톤 ①은 1라운드만 끝까지 갈 수 있다. GDD의 승리 조건은 "3라운드에서 광대 잔고 0"이라 지금은 게임을 이길 수 없고, 라운드가 올라가며 잔고·덱이 커지는 긴장감도 시험할 수 없다.

## Solution

GameManager에 라운드 표(3줄)를 두고, 광대를 파산시키면 Space로 다음 라운드가 시작된다. 3라운드를 깨면 최종 승리, 어느 라운드든 지면 R로 1라운드부터 다시 한다. 화면 맨 위에 `라운드 N / 3`이 보인다. 1라운드의 동작은 그대로다.

## User Stories

1. 플레이어로서, 화면 맨 위에서 지금 몇 라운드인지(`라운드 1 / 3`) 보고 싶다. 잔고와 덱이 왜 바뀌는지 알 수 있도록.
2. 플레이어로서, 1라운드는 지금과 똑같이(잔고 2, 덱 2:3) 시작하길 원한다.
3. 플레이어로서, 광대를 파산시키면 `라운드 N 클리어! - Space로 다음 라운드`를 보고 싶다. 이겼다는 걸 확인하고 준비할 수 있도록.
4. 플레이어로서, 클리어 화면에서 Space를 누르면 다음 라운드가 시작되길 원한다.
5. 플레이어로서, 2라운드는 잔고 3/3, 덱 하락3/상승4로 시작하길 원한다.
6. 플레이어로서, 3라운드는 잔고 4/4, 덱 하락4/상승4로 시작하길 원한다.
7. 플레이어로서, 새 라운드는 레버리지 0, 플레이어 차례, `[보유]` 선택, 빈 결과 줄로 시작하길 원한다.
8. 플레이어로서, 2·3라운드에서 덱이 바닥나면 그 라운드 구성으로 재장전되길 원한다.
9. 플레이어로서, 마지막 캔들로 광대가 파산하면 재장전 없이 바로 클리어가 보이길 원한다.
10. 플레이어로서, 3라운드에서 광대를 파산시키면 `최종 승리! - R로 처음부터`를 보고 싶다.
11. 플레이어로서, 최종 승리 화면에서 Space를 눌러도 아무 일이 없길 원한다(다음 라운드가 없으므로).
12. 플레이어로서, 어느 라운드에서든 내가 파산하면 `패배... - R로 처음부터`를 보고 싶다.
13. 플레이어로서, 패배·클리어·최종 승리 화면에서 R을 누르면 1라운드부터 다시 하고 싶다.
14. 플레이어로서, 플레이 중이나 공개 중에 누른 R·Space·A/D가 라운드를 바꾸지 않길 원한다.
15. 테스터로서, 라운드 표의 각 줄에 고정 순서를 적어 3라운드까지 같은 경우를 재현하고 싶다.
16. 테스터로서, 고정 순서가 그 라운드 구성과 다르면 경고와 함께 무작위로 섞이길 원한다(기존 동작).
17. 개발자로서, 라운드 수치를 코드가 아니라 Inspector 라운드 표 한 곳에서 바꾸고 싶다.
18. 개발자(구술 면담 대비)로서, 라운드 판정(클리어·최종 승리·패배)이 GameManager 한 곳에 있길 원한다.

## Implementation Decisions

- **라운드 표 (데이터):** 한 줄 = 잔고, 하락 수, 상승 수, 고정 순서(문자열). Inspector에 보이는 작은 데이터 묶음(`[Serializable]` 클래스)의 배열 3줄을 GameManager가 가진다. 기본값 2/2/3, 3/3/4, 4/4/4.
- **CandleDeck:** 자기 구성 칸(`Down Count`, `Up Count`, `Fixed Order`)을 없애고, "이번 라운드 구성(하락 수, 상승 수, 고정 순서)을 받는" 함수를 가진다. 받은 구성은 저장해 두고 `Fill()`과 재장전이 그대로 쓴다. `Use Fixed Order` 체크는 덱에 남는다.
- **GameManager (규칙·상태):**
  - 상태에 "지금 라운드 번호"를 추가. `StartRound`가 라운드 번호를 받아 그 줄로 참가자·레버리지·덱을 새로 만든다(Q11).
  - 판정 3가지(파생 값): 플레이어 파산 = 패배 / 광대 파산 + 마지막 라운드 아님 = 라운드 클리어 / 광대 파산 + 마지막 라운드 = 최종 승리. 판정은 GameManager에만 둔다.
  - 실행(Space): 진행 중이면 기존 공개, 라운드 클리어면 다음 라운드, 최종 승리·패배면 무시.
  - 재시작(R): 끝난 화면(클리어·최종 승리·패배)에서만, 항상 1라운드부터.
  - 처리 순서·재장전 조건은 그대로(U2).
- **UIManager:** 맨 위 `라운드 N / 3` 줄, 끝난 화면 문구 3종(클리어·최종 승리·패배).
- **입력·Scene:** Input Actions·PlayerInputHandler는 바꾸지 않는다(Space·R 재사용). Inspector에서 라운드 표 값을 입력한다.
- **Ticket 순서:** 06 데이터만 옮김(동작 그대로) → 07 클리어·다음 라운드·최종 승리 → 08 패배·R 처음부터.

## Testing Decisions

- **좋은 테스트:** 바깥 동작만 본다. "라운드별 고정 순서 + 키 입력 → 화면 글자".
- **seam:** 마일스톤 ①과 같은 1개(라운드 표 고정 순서 + 키 → UI 텍스트).
- **방법:** 위 C1~C9 수동 체크리스트 + AI가 MCP로 Play 실행·Console·화면 캡처(10주차 프롬프트 (e)). 경험은 직접 플레이. 자동 테스트는 하지 않음.
- **퇴행 확인:** 06이 끝나면 `candle-deck-turn` 01~05 시연 순서를 다시 돌린다(U1).
- **선례:** `candle-deck-turn` issues 01~05의 시연 순서·테스트 표.
