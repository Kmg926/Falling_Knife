## 줄별 핵심
| 부분 | 왜 |
|---|---|
| `Execute()`: `if (!IsMonitorOpen) { OpenMonitor(); return; }` | Space·클릭이 "실행" 하나로 묶여 있어서, **닫혀 있을 때의 실행 = 들여다보기**, 열려 있을 때의 실행 = 고른 행동. 입력 코드를 거의 안 바꾸고 흐름(Q1: 열기 → 고르기 → 공개)을 만든다 |
| `IsMonitorOpen = false;` 를 공개 **직전**에 | 화면이 닫히면서 테이블 위 모니터에서 캔들이 자라는 걸 보이게(공개는 판정 코루틴 그대로) |
| `CanOpenMonitor => CanPlayerAct && !IsMonitorOpen` | 열 수 있는 때 = 원래 "내가 행동할 수 있는 때"와 같음. 광대 차례·공개 중·덱 공개 중·멈춤·결과 화면에서는 자동으로 막힘(C1) |
| `BeginPresentation`·`StartRound`·`PassTurn`에서 닫기 | 찌라시로 덱이 비어 재장전 연출이 시작되거나 차례가 넘어가면, 열린 화면이 연출·광대 차례를 가리지 않게 |
| `TogglePause`에 `IsMonitorOpen`이면 무시 | Esc는 "열린 화면 닫기"가 먼저(입력 쪽 순서), 닫힌 뒤에야 일시정지 |
| `MonitorZoomPanel`을 **늘 켜진 HUD**에 붙임 | 확대 화면 묶음(root)을 끄면 그 안의 컴포넌트는 `Awake`가 안 돈다 → 모니터 클릭 버튼 연결이 안 될 수 있어서 |
| 바깥 어두운 판 = 버튼 | "화면 밖 클릭 = 닫기"(제안 7). 패널 그림이 클릭을 먼저 받아 안쪽 클릭은 닫기가 아님 |
| 매수·매도 버튼·아이템 칸은 **옮기기만** | `ActionButtonsView`·`ItemSlotsView` 코드는 그대로(클릭 → 고르고 실행 / 확인 열기). 버튼은 열린 상태에서 `Execute`를 부르므로 바로 공개 |
| 광대 공개 중 위 줄 `광대 매수/매도` | 광대는 모니터를 열지 않으므로(제안 8) 내 모니터에 무엇을 골랐는지 보임. 결과는 캔들이 정하므로 미리 보여도 규칙 문제 없음 |
