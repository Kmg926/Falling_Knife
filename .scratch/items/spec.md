# Spec: 아이템 4종 + 광대 아이템 규칙 (마일스톤 ②)

Status: ready-for-agent

> 근거: 2026-11-09 Grilling Q1~Q17 (모두 사용자 채택, 질문·이유·GDD 원문은 `grilling.md`). GDD 변경 기록 #21(해소 예정), #30~35.
> 기존 기능: `../three-rounds/`, `../clown-ai/`, `../random-deck/`, `../action-log/`(13 결과 문구, 15 기록 없음). 정상 버전(수정 전): 커밋 `3c4d1ca`.
> Spec 작성 중 AI가 제안한 세부 3개(Input Actions는 사용자가 편집 창에서 추가, ClownMove 반환형, 고정 지급 문자열 한 칸)는 2026-11-09 사용자가 **모두 채택**.

## 변경·유지·확인

**변경:** 라운드 시작과 재장전 때 두 사람이 아이템을 2개씩(4종 중 무작위, 최대 4) 받는다. 내 차례에 1~4로 아이템을 확인하고 Space로 쓰거나 Esc로 취소한다. 차트 분석·찌라시·거래 정지·복권이 GDD 효과대로 동작한다. 광대도 GDD 규칙 ①~④(③은 잔고 3 이하)로 아이템을 쓴다.

**유지 (이유):**
- U1 보유·매도 판정, 처리 순서(피해 → 파산 → 재장전), 레버리지 0~3 (핵심 규칙)
- U2 결과 문구 `이름: …` 형식, 광대 생각 1초·공개 0.5초, 행동 기록 없음 (action-log 13·15)
- U3 덱 랜덤 구성·개수 공개, 잔고 10 (random-deck)
- U4 공개 중·광대 차례 입력 무시, R은 끝난 화면에서만 (기존)
- U5 아이템은 "행동"이 아니다: 써도 차례가 넘어가지 않는다 (GDD "행동 전까지 여러 개")

**확인 – 작동 (Play·MCP, 행동 → 예상 결과):**
- C1 라운드 시작: 두 사람 아이템 2개, 화면 `아이템  나: … / 광대: …`
- C2 재장전: 두 사람 +2개, 4개 넘는 것은 버림. 다음 라운드는 0에서 2개
- C3 지급 분포: 많이 뽑으면 4종이 약 25%씩 (MCP)
- C4 1~4 → `확인: 이름 — 설명 / Space 사용, Esc 취소`, 확인 중 A/D 무시, Esc → 아이템 그대로, 빈 슬롯 번호 → 변화 없음
- C5 찌라시: `플레이어: 찌라시 → 다음 캔들은 하락 (버림)`, 남은 개수 1 줄어듦, 차례 그대로. 마지막 캔들이면 재장전 + 아이템 지급
- C6 차트 분석: `차트 분석: 다음 캔들은 상승`이 그 캔들이 공개될 때까지 보임, 찌라시로 버려지면 사라짐
- C7 거래 정지: 광대 잔고 옆 `(정지)` → 내가 차례를 넘기면 `광대: 거래 정지로 턴을 건너뜀` → 다시 내 차례, 정지 풀림. 이미 정지면 `사용 불가`, 아이템 남음
- C8 복권: 고정 결과 4가지 각각(잔고 +1·레버리지 +1·아이템 +1·꽝), 적용 불가(잔고 10·레버리지 3·아이템 가득)면 꽝. 무작위 분포 약 25%씩
- C9 광대: 규칙 ①~④ 순서, 아이템마다 생각 1초 + 결과 줄 `광대: 거래 정지 사용`, 차트 분석 결과는 플레이어에게 숨김, 아이템 하나 뒤 ①부터 다시 판단
- C10 퇴행: 아이템을 쓰지 않으면 기존과 같다 (clown-ai T65~T68 고정 순서, 아이템 고정 지급 빈칸·광대 아이템 없음)

**확인 – 경험 (직접 플레이):** 아이템이 선택을 더 고민하게 만드는가 / 광대 아이템 사용을 따라갈 수 있는가 / 지급량(2개)이 많거나 적지 않은가.

**확인 전:** 구현 전이라 전부 확인 전.

## Problem Statement

지금은 보유·매도 둘뿐이라 매 턴 판단이 "남은 덱 비율"로만 정해진다. GDD의 필수 기능인 아이템 4종이 없어서 정보 확보·덱 조작·턴 빼앗기·역전 같은 선택이 없고, 광대도 GDD 규칙 ④만 쓴다(#21 임시).

## Solution

두 참가자가 아이템 슬롯(최대 4)을 갖고, 라운드 시작·재장전 때 2개씩 무작위로 받는다. 내 차례에 1~4로 확인 → Space로 사용. 효과는 GameManager가 종류별로 처리하고, 이름·설명은 ScriptableObject `ItemData`에 둔다. 광대 판단은 `ClownAI`가 "아이템 사용 또는 보유·매도"를 돌려준다.

## User Stories

1. 플레이어로서, 라운드 시작과 재장전 때 아이템을 받고 싶다.
2. 플레이어로서, 내 아이템과 광대 아이템을 화면에서 보고 싶다.
3. 플레이어로서, 1~4로 아이템을 골라 설명을 본 뒤 쓸지 말지 정하고 싶다.
4. 플레이어로서, 행동하기 전에 아이템을 여러 개 이어서 쓰고 싶다.
5. 플레이어로서, 찌라시로 다음 캔들을 모두 앞에서 버리고 싶다.
6. 플레이어로서, 차트 분석으로 다음 캔들을 나만 보고 싶다.
7. 플레이어로서, 거래 정지로 광대의 다음 턴을 빼앗고 싶다.
8. 플레이어로서, 복권으로 역전 기회를 노리고 싶다(꽝도 있음).
9. 플레이어로서, 광대가 어떤 아이템을 썼는지 결과 줄로 보고 싶다(차트 분석 결과는 모름).
10. 테스터로서, 아이템 지급 순서와 복권 결과를 고정해 같은 경우를 재현하고 싶다.
11. 개발자로서, 아이템 이름·설명을 코드가 아니라 에셋에서 고치고 싶다.
12. 개발자(구술 면담 대비)로서, 효과·판정은 GameManager, 광대 판단은 ClownAI, 보여 주기는 UIManager로 나뉘어 있길 원한다.

## Implementation Decisions

- **아이템 종류:** `enum ItemType { ChartAnalysis, Rumor, TradingHalt, Lottery }` (화면 이름: 차트 분석·찌라시·거래 정지·복권). 테스트 문자열 기호 `C`·`J`·`S`·`L`(Grilling Q13 예 `J C S L`).
- **ItemData (ScriptableObject, Q15):** `type`, `displayName`, `description`. 에셋 4개를 `Assets/_Project/Data/Items/`에. GameManager가 배열로 갖고 화면 이름·설명을 찾는다. 효과 코드는 없다.
- **Participant:** 아이템 목록(최대 4, 넘치면 버림), 거래 정지 상태, 시작 잔고(복권 상한, Q6)와 `Heal(1)`.
- **CandleDeck:** 맨 위를 보기만(`Peek`, 차트 분석), 맨 위를 버리기(`DiscardTop`, 찌라시). 버리기는 `Draw`와 같지만 판정 없음.
- **GameManager (효과·상태):**
  - 지급: `StartRound`에서 두 사람 아이템을 비우고 2개씩, `Reload`에서 2개씩. 결과 줄에 `아이템 +2`. 고정 지급 옵션이 켜져 있으면 문자열에서 순서대로 꺼낸다.
  - 확인 상태: 확인 중인 슬롯 번호(없으면 -1). `SelectItem(slot)`, `Execute()`는 확인 중이면 사용, `Cancel()`. 확인 중 A/D 무시.
  - 사용: 종류별 `switch` — 찌라시(버리고 공개, 비면 재장전), 차트 분석(쓴 사람만 앎), 거래 정지(상대 정지, 이미 정지면 사용 불가), 복권(25%씩, 적용 불가면 꽝, 고정 옵션).
  - 거래 정지 건너뛰기: `PassTurn()`에서 넘겨받은 사람이 정지면 정지를 풀고 `이름: 거래 정지로 턴을 건너뜀`을 붙인 뒤 다시 넘긴다(모든 차례 넘김이 이 한 곳을 지남).
  - 차트 분석으로 아는 캔들: 플레이어용·광대용 따로. 캔들이 공개·버려지거나 재장전되면 지운다.
- **ClownAI:** `Decide`가 "아이템 사용(종류)" 또는 "보유/매도"를 돌려준다. 입력: 남은 하락·상승, 광대 아이템, 광대 잔고, 플레이어 정지 여부, 광대가 아는 다음 캔들, 복권 기준값(3). 규칙 ①~④ 순서. 광대 턴은 결정 하나마다 생각 1초 → 아이템이면 쓰고 다시 생각, 행동이면 기존 공개.
- **UIManager:** `아이템  나: … / 광대: …` 줄, 잔고 줄 `(정지)`, 확인 중 줄, 플레이어 차트 분석 줄.
- **입력:** Input Actions `Game` 맵에 `Item1`~`Item4`(1~4 키), `Cancel`(Esc) 추가. PlayerInputHandler에 칸 5개 추가 → GameManager 호출만.
  - (AI 제안 → 사용자 채택): `.inputactions`는 Unity Input Actions 편집 창에서 사용자가 추가한다(Ticket 02 때와 같은 방식, 수업 실습과 같은 화면). 또는 사용자가 허락하면 AI가 MCP로 추가.
- **(AI 제안 → 사용자 채택) — ClownAI 반환형:** 작은 데이터 묶음 `ClownMove`(아이템을 쓰는지, 어떤 아이템인지, 아니면 보유/매도)를 돌려준다. 지금처럼 `PlayerAction`만 돌려주면 아이템 사용을 표현할 수 없다.
- **(AI 제안 → 사용자 채택) — 고정 지급 문자열:** 한 판 동안 지급할 때마다 앞에서부터 순서대로 꺼내고(플레이어 2개 → 광대 2개 순), 다 쓰면 무작위. 라운드 표 줄마다 두지 않고 GameManager에 한 칸.
- **Ticket 순서 (Q12):** 16 지급·확인·찌라시(C1~C5, C10) → 17 차트 분석(C6) / 18 거래 정지(C7) / 19 복권(C8) (17~19는 16 뒤 아무 순서) → 20 광대 아이템(C9).

## Testing Decisions

- **좋은 테스트:** 바깥 동작만. "고정 덱 + 고정 아이템 + 입력 → 화면 글자".
- **seam:** ① 기존(고정 순서 + 함수/키 → UI 텍스트) ② 고정 아이템 지급 문자열 ③ 복권 결과 고정 ④ `ClownAI.Decide`에 상황을 넣어 결과 보기(09 T59처럼) ⑤ 무작위는 많이 뽑아 분포(C3, C8).
- **방법:** C1~C10 + MCP 캡처. 테스트 전 컴파일 시각 > 저장 시각, Scene 저장 전 다른 변경 확인.
