## 변경·유지·확인

**변경:** 사건마다 효과음(충격음·초침·클릭·셔플)이 한 번씩 난다. 피해를 입으면 가운데 글자가 0.2초 빨갛게 깜빡이고, 내 잔고가 3 이하면 잔고 줄이 계속 어두운 빨강이다. 배경음악 자리를 만들고 캔들 공개 중에는 음악을 약 20%로 줄인다. 소리 크기는 전체·음악 두 칸(0~1).

**바꾸지 않을 것 (12주차 "한 줄") / 유지 (이유):**
- U1 판정·처리 순서·잔고·레버리지·덱·아이템 규칙 그대로 (12주차: 반응은 판정을 바꾸지 않음)
- U2 시간 그대로: 공개 0.5초, 광대 생각 1초. 반응·소리가 기다리는 시간을 늘리지 않음
- U3 결과 문구·화면 줄 구성 그대로 (색만 더함)
- U4 입력 규칙 그대로 (소리는 결과일 뿐 입력을 막지 않음)
- U5 배경음악은 AI로 만들지 않음 (사용자 결정)

**사건별 알아차릴 정보 (12주차 "한 문장"):**
- 피해: "하락이 나와 누군가의 잔고가 줄었다" → 충격음 + 글자 빨강 깜빡임
- 공개: "이제 캔들이 뒤집힌다" → 음악 작아짐 + 초침
- 선택: "내 선택이 바뀌었다" → 클릭
- 재장전: "덱이 새로 섞였다" → 셔플
- 상태(긴장): "내 잔고가 위험하다(3 이하)" → 잔고 줄 어두운 빨강

**확인 – 작동 (Play·MCP, 행동 → 예상 결과):**
- C1 후보 12개(4종 × 3): 길이·앞 무음·최대 음량 표, 길이가 정한 범위 안
- C2 하락 피해 1번 → 충격음 1번(보유·매도, 플레이어·광대 모두)
- C3 공개 1번 → 초침 1번, 공개 동안 음악 약 20% → 결과 때 원래대로
- C4 선택이 바뀔 때 클릭 1번, 아이템 확인·취소 때 클릭
- C5 재장전 → 셔플 1번
- C6 전체 크기 0 → 효과음·음악 모두 무음 / 음악 크기 0 → 음악만 무음
- C7 피해 1번 → 글자 0.2초 빨강 1번(연속 피해면 다시 시작), 판정·시간 그대로
- C8 내 잔고 3 이하 → 잔고 줄 어두운 빨강, 회복으로 4 이상 → 원래 색
- C9 배경음악 칸이 비어 있어도 오류 없음 / 곡을 넣으면 반복 재생
- C10 퇴행: `clown-ai` T65~T68, 아이템 흐름 결과 같음, Console 오류 0

**확인 – 경험 (직접 플레이·스피커):** 소리 크기·톤이 어울리는가, 클릭이 거슬리지 않는가, 깜빡임이 결과 글자를 가리지 않는가, 긴장 표시가 보이는가. 소리는 MCP로 들을 수 없으므로 "직접 확인 필요".

**확인 전:** 구현 전이라 전부 확인 전.

## Problem Statement

지금 게임은 소리가 전혀 없고 화면은 글자만 바뀐다. 피해를 입어도, 캔들이 공개돼도, 덱이 섞여도 같은 모습이라 사건의 무게가 전해지지 않는다(12주차 "화면과 소리로 몰입 만들기"). GDD는 낮은 저음·초침·둔탁한 충격음·공개 직전 무음을 계획했다.

## Solution

AI가 코드로 효과음 후보를 만들고(`tools/`), 사용자가 듣고 고른 4개를 `AudioManager`가 튼다. GameManager가 사건이 일어난 자리에서 AudioManager와 UIManager를 한 번씩 부른다. UIManager는 피해 깜빡임과 잔고 긴장 색을 보여 준다. 배경음악은 빈 칸으로 두고 사용자가 곡을 넣는다.

## User Stories

1. 플레이어로서, 하락으로 잔고가 줄면 둔탁한 소리와 빨간 깜빡임으로 바로 알고 싶다.
2. 플레이어로서, 캔들이 뒤집히는 순간 음악이 잦아들고 초침이 들리길 원한다(긴장).
3. 플레이어로서, 보유·매도를 바꿀 때 짧은 클릭으로 입력이 먹혔음을 알고 싶다.
4. 플레이어로서, 덱이 새로 섞이면 셔플 소리로 알고 싶다(새 구성을 기억해야 하므로).
5. 플레이어로서, 내 잔고가 위험하면 화면에서 계속 느끼고 싶다.
6. 플레이어로서, 배경에 어두운 하우스·테크노 음악이 흐르길 원한다.
7. 플레이어로서, 소리 크기를 0으로 하면 완전히 조용하길 원한다.
8. 개발자로서, 효과음 후보를 직접 듣고 고르고 싶다(AI는 고르지 않음).
9. 개발자로서, 배경음악 곡을 나중에 Inspector 칸에 넣기만 하면 되길 원한다.
10. 개발자(구술 면담 대비)로서, 판정은 GameManager, 소리는 AudioManager, 화면은 UIManager로 나뉘어 있길 원한다.

## Implementation Decisions

- **효과음 만들기 (`tools/make_sfx.py`, AI 작성 — Q3):** numpy로 합성, 44.1kHz 모노 16bit WAV. 소리마다 후보 A·B·C(톤·감쇠만 다름) → `.scratch/art-sound/candidates/<이름>-<A|B|C>.wav`, 측정표(길이·앞 무음·최대 dBFS) 출력. 고른 4개를 `Assets/_Project/Audio/Sounds/{impact,tick,click,shuffle}.wav`로 복사(Unity가 .meta 생성).
- **AudioManager (새 MonoBehaviour):** 효과음 칸 4개(`AudioClip`), 효과음용·음악용 `AudioSource` 칸 2개, `[Range(0,1)]` 전체·음악 크기, 공개 중 음악 비율(0.2). 함수: `PlayImpact()`·`PlayTick()`·`PlayClick()`·`PlayShuffle()`, `SetRevealDuck(bool)`. 효과음은 `PlayOneShot(clip, 전체 크기)`, 음악 크기 = 전체 × 음악 × (공개 중이면 0.2). 클립이 비어 있으면 아무것도 안 함.
- **GameManager (부르는 줄만 추가):** `[SerializeField] AudioManager audioManager`. 하락 피해 자리(`ResolveHold` 하락, `ResolveSell` 하락) → `PlayImpact()` + `ui.FlashDamage()`. `RevealRoutine` 시작 → `SetRevealDuck(true)` + 초침, 끝 → `SetRevealDuck(false)`. `Reload()` → `PlayShuffle()`. `Select()`·`SelectItem()`·`CancelItem()` → `PlayClick()`.
  - (AI 제안 → 사용자 채택) **초침 타이밍:** 공개 시작과 동시에 음악을 줄이고, **0.2초 뒤** 초침 한 번(앞 0.2초가 GDD "공개 직전 잠깐 무음"). 공개 시간 0.5초는 그대로(U2).
  - (AI 제안 → 사용자 채택) **클릭은 선택이 실제로 바뀔 때만:** 같은 쪽을 다시 누르면 소리 없음(12주차 "한 번만", 거슬림 방지).
- **UIManager:** `FlashDamage()` = 상태 글자 색을 0.2초 빨강 → 원래 색(코루틴, 진행 중이면 다시 시작). `Refresh`에서 내 잔고 ≤ 긴장 기준(Inspector, 3)이면 잔고 줄을 TMP 색 태그(`<color=…>`)로 어두운 빨강.
- **Scene:** `Audio` 오브젝트(AudioManager + AudioSource 2개, 음악은 Loop·Play On Awake), 클립·참조 연결. Main Camera에 AudioListener 이미 있음(확인한 사실).
  - (AI 제안 → 사용자 채택) **Scene 연결은 AI가 MCP로**(16과 같은 방식, 저장 전 변경 확인). 원하면 Inspector 순서 안내로 대체.
- **Ticket 순서 (Q12):** 21 효과음(C1~C6) → 22 화면 반응(C7·C8) → 23 배경음악 자리(C9). C10은 매번.

## Testing Decisions

- **좋은 테스트:** 바깥 동작만. 소리는 MCP로 들을 수 없으므로 "효과음 `AudioSource`가 그 순간 재생 중인가(`isPlaying`)·음악 `volume` 값"으로 확인하고, 실제 소리는 사용자가 스피커로(12주차 "직접 확인 필요").
- **seam:** ① 고정 덱·아이템 + 함수 호출 → AudioSource 상태·글자 색 ② 후보 측정표.
- **방법:** C1~C10 + MCP 캡처(깜빡임·긴장 색). 테스트 전 컴파일 시각, Scene 저장 전 변경 확인.

## Out of Scope

- 배경음악 곡 자체(사용자가 확보, AI 생성 안 함)
