# Spec: 캔들 덱 + 보유/매도 한 턴 (마일스톤 ①)

Status: ready-for-agent

> 근거: 2026-11-02 Grilling Q1~Q25 (모두 사용자 채택, 질문·추천 이유·결정은 `grilling.md`). GDD 원문(PDF)은 직접 대조하지 못했고 CLAUDE.md 2장 요약을 기준으로 했다.

## Problem Statement

Falling Knife의 핵심 재미는 "숨겨진 캔들 덱에서 다음 카드가 하락일지 상승일지 판단해 보유·매도를 고르는 것"이다. 아직 Unity 프로젝트에는 이 규칙이 하나도 없어서, 규칙 수치(잔고 2, 덱 하락2:상승3, 레버리지 0~3)가 실제로 긴장감을 주는지 플레이해 볼 수 없다. 아이템·AI·정식 UI보다 먼저, 텍스트만으로 1라운드를 끝까지 돌려 볼 수 있어야 한다.

## Solution

GameScene에서 Play를 누르면 텍스트 UI에 플레이어·광대 잔고, 레버리지, 남은 하락·상승 개수, 지금 차례가 보인다. 차례인 사람이 보유 또는 매도를 골라 실행하면 덱 맨 위 캔들이 1초 동안 공개되고, GDD 04장 규칙대로 잔고·레버리지·턴이 바뀐다. 광대 차례도 같은 키로 사람이 대신 조작한다(핫시트). 덱이 바닥나면 같은 구성으로 재장전되고, 한쪽 잔고가 0이 되면 승패가 표시되며 R로 다시 시작한다. 덱 순서를 Inspector에서 고정할 수 있어 모든 경우를 재현해 시험할 수 있다.

## User Stories

1. 플레이어로서, Play를 누르면 바로 1라운드가 시작되길 원한다. 별도 메뉴 없이 규칙을 시험할 수 있도록.
2. 플레이어로서, 시작할 때 내 잔고 2·광대 잔고 2가 보이길 원한다. 얼마나 버틸 수 있는지 알 수 있도록.
3. 플레이어로서, 레버리지가 0에서 시작하는 것을 보고 싶다. 첫 피해 크기를 예상할 수 있도록.
4. 플레이어로서, 남은 하락·상승 개수(시작 2/3)가 계속 보이길 원한다. 확률을 계산해 보유·매도를 고를 수 있도록.
5. 플레이어로서, 1라운드는 내가 먼저 시작하길 원한다. 처음 하는 사람이 바로 조작해 볼 수 있도록.
6. 플레이어로서, 지금 누구 차례인지(플레이어/광대) 항상 보이길 원한다. 핫시트에서 헷갈리지 않도록.
7. 플레이어로서, A/D 또는 ←/→로 보유·매도 중 하나를 고르고 고른 쪽이 괄호로 표시되길 원한다. 실행 전에 선택을 확인할 수 있도록.
8. 플레이어로서, Space로 고른 행동을 실행하길 원한다.
9. 플레이어로서, 실행하면 캔들이 1초 동안 "공개 중…"으로 표시되길 원한다. 결과를 놓치지 않도록.
10. 플레이어로서, 공개 중에 누른 키는 무시되길 원한다. 실수로 두 번 실행되지 않도록.
11. 플레이어로서, 보유했는데 상승이면 레버리지가 1 오르고 내 차례가 계속되길 원한다. 더 크게 걸지 계속 판단할 수 있도록.
12. 플레이어로서, 레버리지가 3일 때 보유+상승이 나오면 3에 머물길 원한다. 상한 규칙이 지켜지도록.
13. 플레이어로서, 보유했는데 하락이면 내 잔고가 (1+레버리지)만큼 줄고 레버리지가 0이 되며 턴이 넘어가길 원한다.
14. 플레이어로서, 매도했는데 하락이면 상대 잔고가 (1+레버리지)만큼 줄고 레버리지가 0이 되며 턴이 넘어가길 원한다.
15. 플레이어로서, 매도했는데 상승이면 잔고·레버리지는 그대로이고 턴만 넘어가길 원한다. 쌓인 레버리지가 상대에게 넘어가는 긴장을 느낄 수 있도록.
16. 플레이어로서, 잔고가 피해보다 작아도 0 밑으로 내려가지 않고 0으로 표시되길 원한다.
17. 플레이어로서, 방금 공개된 캔들과 결과(예: "하락! 플레이어 −2")가 한 줄로 보이길 원한다. 무슨 일이 일어났는지 바로 알 수 있도록.
18. 핫시트 테스터로서, 광대 차례에도 같은 키로 광대의 보유·매도를 고르길 원한다. AI 없이 모든 분기를 시험할 수 있도록.
19. 핫시트 테스터로서, 차례가 바뀌면 선택이 보유로 돌아가길 원한다. 직전 사람의 선택을 실수로 그대로 실행하지 않도록.
20. 플레이어로서, 덱이 바닥나면 같은 구성(하락2/상승3)으로 다시 섞여 채워지길 원한다. 승부가 안 난 채로 멈추지 않도록.
21. 플레이어로서, 재장전될 때 "덱 재장전 (하락2 / 상승3)"이 한 번 보이길 원한다. 남은 개수가 갑자기 늘어난 이유를 알 수 있도록.
22. 플레이어로서, 마지막 카드로 누군가 파산하면 재장전보다 승패가 먼저 처리되길 원한다(피해 → 잔고 0 판정 → 덱 소진 확인).
23. 플레이어로서, 광대 잔고가 0이 되면 "승리", 내 잔고가 0이 되면 "패배"가 보이길 원한다.
24. 플레이어로서, 승패가 나온 뒤 R을 누르면 잔고·레버리지·덱·차례가 처음 상태로 돌아가길 원한다. Play를 다시 누르지 않고 반복 테스트할 수 있도록.
25. 플레이어로서, 플레이 중이나 공개 중에 누른 R은 무시되길 원한다. 판이 실수로 날아가지 않도록.
26. 테스터로서, Inspector에서 "고정 순서"를 켜고 `D U U D U`처럼 덱 순서를 적고 싶다. 테스트 표의 같은 경우를 언제든 다시 만들 수 있도록.
27. 테스터로서, 고정 순서가 덱 구성과 맞지 않으면 Console 경고와 함께 무작위 섞기로 돌아가길 원한다. 잘못된 입력으로 규칙이 깨지지 않도록.
28. 개발자로서, 라운드 수치(잔고, 하락·상승 수)를 코드에 박지 않고 바꿀 수 있길 원한다. 마일스톤 ②에서 2·3라운드 값을 넣을 수 있도록.
29. 개발자(구술 면담 대비)로서, 규칙 판정과 처리 순서가 한 곳에만 있길 원한다. 어디서 무엇이 결정되는지 설명할 수 있도록.

## Implementation Decisions

- **모듈 6개 (마일스톤 ①)**
  - `CandleDeck`: 라운드 시작 시 하락·상승 카드를 한 번 섞어 순서를 정해 둔다(Fisher-Yates). 맨 위 한 장 공개, 남은 하락·상승 개수, 비었는지, 같은 구성으로 재장전. 테스트용 고정 순서 옵션(D/U 문자열, 구성 불일치 시 경고 후 무작위).
  - `LeverageCounter`: 공용 레버리지 0~3. 올리기(3에서 멈춤), 0으로 돌리기, 현재 값. GDD 08장의 `StackCounter`를 용어에 맞춰 이름 변경.
  - `Participant`: 이름, 잔고, 피해 받기(0 밑으로 내려가지 않음), 파산 여부. 플레이어·광대 각각 하나.
  - `GameManager`: 차례, 행동 실행, 규칙 판정, 처리 순서(피해 → 잔고 0 판정 → 덱 소진 확인), 공개 중·라운드 종료 상태, 재시작. **규칙 판정은 여기에만 둔다.**
  - `PlayerInputHandler`: Input Actions의 행동을 받아 `GameManager`에 전달. 공개 중이면 무시. 핫시트이므로 차례와 관계없이 같은 입력을 쓴다.
  - `UIManager`: 상태를 Canvas 위 TextMeshPro 글자로 표시(아래 7항목).
- **규칙 표 (GDD 04장, 1라운드)**

  | 행동 | 공개 | 잔고 | 레버리지 | 턴 |
  |---|---|---|---|---|
  | 보유 | 상승 | 변화 없음 | +1 (최대 3) | 유지 |
  | 보유 | 하락 | 나 −(1+레버리지) | 0 | 넘김 |
  | 매도 | 하락 | 상대 −(1+레버리지) | 0 | 넘김 |
  | 매도 | 상승 | 변화 없음 | 그대로 | 넘김 |

- **라운드 수치:** 잔고 2/2, 덱 하락2:상승3. Inspector에서 바꿀 수 있는 값으로 둔다(2·3라운드 대비). 레버리지는 라운드 시작 시 0. 1라운드 선공은 플레이어.
- **공개 연출:** 실행 → "공개 중…" 1초(코루틴 하나) → 결과 적용. 이 동안 모든 입력 무시.
- **입력:** Input Actions 에셋 하나에 `Select`(A/D, ←/→), `Execute`(Space), `Restart`(R). 마우스 클릭은 ②에서 버튼과 함께 추가. Restart는 라운드 종료 화면에서만 받는다. R은 테스트용이라 최종 빌드 전에 제거한다.
- **선택 상태:** 보유/매도 중 하나. 차례가 바뀔 때마다 보유로 초기화.
- **텍스트 UI 7항목:** ① 지금 차례 ② 선택(`[보유]  매도`) ③ 플레이어/광대 잔고 ④ 레버리지 ⑤ 남은 하락/상승 ⑥ 방금 공개된 캔들과 결과 한 줄(재장전 알림 포함) ⑦ "공개 중…" 또는 "승리/패배 — R로 재시작"
- **Scene:** 새 GameScene에서 작업한다. SampleScene은 쓰지 않는다.
- **코드 반영 방식:** AI는 Ticket 단위 초안만 쓰고, 사용자가 직접 다시 타이핑해 반영한다(CLAUDE.md 4장).

## Testing Decisions

- **좋은 테스트:** 바깥에서 보이는 동작만 확인한다. "고정 덱 순서 + 누른 키 → 화면 글자" 비교. 내부 변수나 함수 호출 순서는 보지 않는다.
- **테스트 seam 1개:** `CandleDeck` 고정 순서로 덱을 정하고, Play 모드에서 키를 눌러, `UIManager` 텍스트 7항목을 확인한다. 개별 모듈 단위 테스트는 하지 않는다.
- **방법:** 수동 체크리스트(T-번호, 덱 순서, 입력, 기대 화면, 결과). 자동(EditMode) 테스트는 ①에서 하지 않는다.
- **꼭 들어갈 경우:** 규칙 표 4칸 각각, 레버리지 3 상한, 레버리지 2에서 하락 피해 3, 잔고 0 밑으로 안 내려감, 공개 중 입력 무시, 차례 바뀐 뒤 선택 보유로 초기화, 재장전과 알림, 마지막 카드로 파산 시 재장전보다 승패 먼저, 결과 화면 외 R 무시, R 재시작 후 초기 상태, 잘못된 고정 순서 경고.
- **선례:** 이 프로젝트에는 아직 테스트가 없다. 강의 실습의 T01~T08 수동 테스트 표 형식을 따른다.
