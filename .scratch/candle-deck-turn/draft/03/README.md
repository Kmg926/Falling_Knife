## 2. 바뀐 줄마다 왜

| 줄 | 왜 |
|---|---|
| `Participant Opponent => (Current == Player) ? Clown : Player;` | "지금 차례가 아닌 쪽"을 이름 하나로. 매도 피해 대상과 차례 넘기기 두 곳에서 같은 계산을 쓰므로 한 곳에 모았다 |
| `Execute()`에서 매도 안내 분기 삭제 | 02의 임시 처리("03에서 구현")를 없앴다 |
| `StartCoroutine(RevealRoutine(Selected))` | **실행한 순간의 선택**을 코루틴에 넘긴다. 공개 중엔 선택이 안 바뀌지만(02), "무엇을 실행했는지"를 코루틴이 직접 들고 있어야 나중에 규칙이 늘어도 헷갈리지 않는다 |
| `RevealRoutine(PlayerAction action)` | 매개변수로 받은 행동대로 판정 |
| `if (action == PlayerAction.Hold) ResolveHold(candle); else ResolveSell(candle);` | 보유/매도 갈림길. 판정은 여전히 GameManager 한 곳 |
| `ResolveHold`의 결과 줄에 `보유 →` | 결과 줄만 보고 무슨 행동이었는지 알게. 매도와 구분 |
| `ResolveSell` 하락: `int damage = 1 + Leverage.Value;` | 보유와 같은 피해 공식(규칙 표). **Reset 전에** 계산 |
| `Opponent.TakeDamage(damage)` | 매도는 상대에게 건 것이라 **상대**가 맞는다. 보유(`Current`)와 이 한 단어가 다르다 |
| `Leverage.Reset()` | 피해가 들어갔으니 0 |
| `LastResult`를 `PassTurn()` **전에** 만든다 | PassTurn 뒤엔 `Opponent`가 바뀌어(맞은 사람이 Current가 됨) 이름이 틀어진다 |
| 상승: `변화 없음 (레버리지 N 그대로)` | 매도+상승은 잔고·레버리지 그대로, 레버리지는 공용이라 **그 값 그대로 상대 차례로 넘어간다**(Q7) |
| `PassTurn()`이 if/else **밖** | 매도는 결과와 상관없이 항상 차례를 넘긴다 |
| `PassTurn()`의 `Current = Opponent;` | 02의 `? :` 계산을 `Opponent`로 바꿨다. 동작은 같다 |

> 결과 줄에 `→`(화살표)를 썼다. Galmuri에 들어 있는 글자(KS X 1001 기호)라 보일 것으로 예상하지만 **확인하지 못했다.** □로 보이면 `>`로 바꾼다.
