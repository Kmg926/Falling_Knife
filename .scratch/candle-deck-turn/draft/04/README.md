## 2. 바뀐 줄마다 왜

### Participant.cs
| 줄 | 왜 |
|---|---|
| `public bool IsBankrupt => Balance == 0;` | 파산 = 잔고 0(GLOSSARY). 잔고는 0 밑으로 안 내려가므로(02) `== 0`이면 충분 |

### GameManager.cs
| 줄 | 왜 |
|---|---|
| `bool SomeoneBankrupt => Player.IsBankrupt \|\| Clown.IsBankrupt;` | 둘 중 하나라도 파산. `\|\|`는 "또는" |
| `Execute()`의 빈 덱 안내 문구 변경 | 04부터 덱이 비는 경우는 "마지막 캔들로 파산해서 재장전을 건너뛴" 경우뿐. 그때는 05가 입력을 막을 예정 |
| 주석 `① 피해 → ② 잔고 0 판정 → ③ 덱 소진 확인` | GDD 04장 처리 순서. **파산이 재장전보다 먼저**(Q3) |
| `ResolveHold/ResolveSell` 호출 (그대로) | ① 피해 적용 |
| `if (!SomeoneBankrupt && deck.IsEmpty)` | ② 파산이 아니고(`!` = 아니다) **그리고**(`&&`) ③ 덱이 비었을 때만 재장전. 마지막 캔들로 파산하면 재장전하지 않는다 |
| `Reload()` → `deck.Fill()` | 같은 구성으로 다시 섞기. 고정 순서를 켜 두면 재장전도 같은 고정 순서 |
| `LastResult += $"\n덱 재장전 (...)"` | `+=`는 "뒤에 이어 붙이기". 방금 결과 줄 아래에 재장전 알림을 **한 번** 붙인다(Q24). 다음 공개 때 `LastResult`가 새로 덮어써지므로 저절로 사라진다 |
| 개수를 `deck.RemainingDown/Up`에서 읽음 | 숫자를 직접 쓰지 않아 2·3라운드 구성에서도 맞게 나온다 |
| `Reload()`가 잔고·레버리지·`Current`를 안 건드림 | 재장전은 덱만 바꾼다(수락 기준) |

> 화면 마지막 줄이 2줄이 될 수 있다(결과 + 재장전). `StatusText`가 잘리면 `Height`를 늘린다(예: 600).

## 4. 수동 테스트 (Ticket 04)

> 덱 기본(하락2/상승3). 정지 상태에서 고정 순서 설정. 끝나면 고정 끄기 → Ctrl+S.
> 매도는 매번 **D를 누른 뒤** Space(차례가 바뀌면 선택이 보유로 돌아가므로).

| # | 고정 순서 | 입력 | 기대 화면 |
|---|---|---|---|
| T25 | `D U U D U` | (D → Space) × 5 | 5번째 뒤: 결과 줄 아래 `덱 재장전 (하락2 / 상승3)`, 남은 캔들 **2 / 3**, 잔고 **1 / 1**, 레버리지 0, 차례 **광대**(재장전 전과 같음). Console에 덱 순서가 **한 번 더** 찍힘(`Down Up Up Down Up`) |
| T26 | 이어서 | Space | 재장전 줄이 사라지고 보통 결과 줄만 |
| T27 | `U U D U D` | (D → Space) × 5 | 5번째(하락)에서 `광대 -1`, 광대 잔고 **0**, 재장전 줄 **없음**, 남은 캔들 0 / 0, Console에 새 덱 순서 **없음** |
| T28 | 이어서 | Space | 화면 변화 없음, Console "덱이 비어 실행할 수 없습니다…05" |
| T29 | 고정 끔 | 자유롭게 10번 이상 | 덱이 여러 번 재장전돼도 오류 없음 |
