> 기존 기능: `../three-rounds/`(라운드 표), `../clown-ai/`(광대 AI, 남은 개수로 판단). 정상 버전(수정 전): 커밋 `a017980`.
> Spec 작성 중 AI가 제안한 세부 2개(범위 안전장치, 고정 순서 규칙)는 2026-11-09 사용자가 **둘 다 채택**.

## 변경·유지·확인

**변경:** 덱을 채울 때마다(라운드 시작·재장전) 그 라운드의 총 장수 범위(4~6 / 6~8 / 7~9) 안에서 총 장수를, 1 ~ (총 장수 − 1)에서 하락 수를 랜덤으로 뽑는다. 시작 잔고는 3라운드 모두 10이다.

**유지 (이유):**
- U1 순서는 Fisher-Yates로 섞고 숨긴다, 개수는 화면 `남은 캔들` 줄에 공개한다 (GDD "공개 후 셔플")
- U2 처리 순서 피해 → 파산 → 재장전 (GDD). 재장전 문구 `덱 재장전 (하락N / 상승M)`이 새 구성을 공개한다
- U3 광대 AI는 그대로: 남은 하락·상승 수만 보고 판단 (코드 변경 없음)
- U4 3라운드 흐름(클리어·최종 승리·패배·R)과 광대 턴 흐름 그대로 (`three-rounds`, `clown-ai` C1~C9)
- U5 테스트용 고정 순서는 계속 쓸 수 있다 — 이제 문자열이 개수와 순서를 둘 다 정한다 (Q5)

**확인 – 작동 (Play 모드·MCP, 행동 → 예상 결과):**
- C1 Play → 1라운드 `남은 캔들` 하락+상승 합이 4~6, 하락 ≥ 1, 상승 ≥ 1
- C2 MCP로 라운드별 구성 뽑기를 1000번 반복 → 총 장수가 항상 범위 안이고 범위의 모든 값이 나온다, 하락은 항상 1 ~ 총−1이고 그 사이 값이 모두 나온다 (GDD F01 "셔플 100회 로그로 구성 확인"을 이어받음)
- C3 재장전 → `덱 재장전 (하락N / 상승M)`의 N+M이 그 라운드 범위 안. 재장전을 여러 번 하면 구성이 바뀔 수 있다
- C4 2라운드 시작 합 6~8, 3라운드 시작 합 7~9
- C5 고정 순서 `D U U` + `Use Fixed Order` → 덱이 정확히 3장 `Down Up Up`, 경고 없음 / 고정 순서 빈칸 줄은 경고 없이 랜덤 / D·U·공백 외 글자는 경고 + 랜덤
- C6 퇴행: `clown-ai` T65~T68 고정 순서가 그대로 통과 (Ticket 11까지는 잔고 2/3/4 유지)
- C7 (Ticket 12) 시작 잔고 10/10/10, 3라운드 완주 가능
- C8 (Ticket 12) MCP 자동 대전 20판(플레이어 자리도 광대 규칙): 판마다 행동 수·재장전 수·걸린 시간·결과 기록 → GDD 3~5분과 비교

**확인 – 경험 (직접 플레이):** 라운드가 올라갈 때 차이가 느껴지는가(덱 크기만 다름) / 잔고 10이 너무 길지 않은가. 숫자 조정은 한 번에 하나.

**확인 전:** 구현 전이라 전부 확인 전.

## Problem Statement

지금 덱은 라운드마다 하락·상승 개수가 고정(2:3 / 3:4 / 4:4)이라 매 판 같은 구성으로 시작한다. 사용자는 라운드마다 캔들의 종류와 수가 랜덤이길 원하고, 잔고(체력)도 2~4는 너무 빨리 끝난다고 판단해 10으로 크게 늘리기로 했다.

## Solution

라운드 표 한 줄을 "잔고 / 최소 장수 / 최대 장수 / 고정 순서"로 바꾼다. CandleDeck은 채울 때마다 범위 안에서 총 장수와 하락 수를 새로 뽑아 섞는다. 고정 순서를 켜면 문자열이 그대로 덱이 된다. 잔고는 라운드 표 값을 10으로 바꾼다.

## User Stories

1. 플레이어로서, 판마다·라운드마다 덱 구성이 달라지길 원한다. 같은 판을 반복하는 느낌이 없도록.
2. 플레이어로서, 라운드가 시작되면 이번 덱의 하락·상승 개수를 보고 싶다(순서는 모름).
3. 플레이어로서, 재장전되면 새 구성을 문구로 보고 싶다.
4. 플레이어로서, 덱에 하락과 상승이 최소 1장씩은 있길 원한다(한쪽만 있으면 고민할 게 없음).
5. 플레이어로서, 뒤 라운드일수록 덱이 길어지길 원한다.
6. 플레이어로서, 잔고 10으로 시작해 레버리지를 키우며 여러 번 주고받고 싶다.
7. 테스터로서, 고정 순서 문자열 하나로 덱 개수와 순서를 정해 같은 경우를 재현하고 싶다.
8. 테스터로서, 고정 순서를 비워 둔 라운드는 경고 없이 랜덤이길 원한다.
9. 개발자로서, 범위·잔고를 코드가 아니라 Inspector 라운드 표에서 바꾸고 싶다.
10. 개발자(구술 면담 대비)로서, "덱을 어떻게 채우나"는 CandleDeck 한 곳에 있길 원한다.

## Implementation Decisions

- **RoundConfig (데이터):** `startingBalance`, `minCards`, `maxCards`, `fixedOrder`. `downCount`·`upCount` 삭제.
  - 주의(코드에서 확인한 사실): Scene에는 이미 라운드 3줄 값이 저장돼 있다(`startingBalance 2/3/4`, `downCount`, `upCount`). 새 칸 `minCards`·`maxCards`는 기존 줄에 RoundConfig의 기본값(모든 줄 같은 값)으로 들어오므로, **Inspector에서 줄마다 4~6 / 6~8 / 7~9를 직접 입력**해야 한다. GameManager 코드의 배열 기본값은 새로 붙인 컴포넌트에만 쓰인다.
- **CandleDeck (덱 채우기):**
  - `SetComposition(int minCards, int maxCards, string order)`: 범위와 고정 순서를 저장.
  - `Fill()`: 고정 순서를 쓸 수 있으면 문자열대로, 아니면 `총 = Random.Range(minCards, maxCards + 1)`, `하락 = Random.Range(1, 총)`, `상승 = 총 − 하락` → 기존 Fisher-Yates.
    - `Random.Range(int, int)`는 **끝 값을 포함하지 않는다** → `maxCards + 1`, 하락은 `Random.Range(1, 총)`이 곧 1 ~ 총−1.
  - (AI 제안 → 사용자 채택) 안전장치: `minCards < 2`이면 2로, `maxCards < minCards`이면 `minCards`로 맞추고 경고(하락·상승 1장씩이 불가능해지는 값 방지).
  - (AI 제안 → 사용자 채택) 고정 순서 규칙: `Use Fixed Order` 켜짐 + 문자열이 **빈칸이 아니고** D/U/공백만 → 그대로 사용(개수 비교·경고 없음). 빈칸 → 경고 없이 랜덤. 다른 글자 → 경고 + 랜덤. 하락·상승 최소 1장 규칙은 테스트용 문자열에는 적용하지 않음(일부러 한쪽만 넣는 시험도 가능하게).
- **GameManager:** `deck.SetComposition(config.minCards, config.maxCards, config.fixedOrder)`로 한 줄 바꿈, 배열 기본값을 `10, 4, 6` / `10, 6, 8` / `10, 7, 9`로. 판정·재장전·광대 코드 그대로.
- **UIManager·ClownAI·PlayerInputHandler:** 변경 없음.
- **Ticket 순서 (Q11):** 11 덱 구성 랜덤(코드, C1~C6) → 12 잔고 10 + 길이 측정(Inspector 값, C7~C8).

## Testing Decisions

- **좋은 테스트:** 바깥 동작만 본다. 랜덤은 한 번으로 판단할 수 없으므로 **많이 뽑아 분포를 본다**(C2).
- **seam 3개:** ① `CandleDeck.SetComposition` + `Fill()` 반복 → `RemainingDown/Up` (MCP, Play 밖에서도 가능) ② 기존 고정 순서 + 키/함수 → UI 텍스트 ③ 자동 대전(플레이어 자리도 `ClownAI.Decide`) 로그.
- **방법:** C1~C8 + AI가 MCP로 Play·Console·캡처. 테스트 전 컴파일 시각 > 저장 시각 확인. 경험은 직접 플레이. 자동 테스트 프레임워크는 쓰지 않음.
- **선례:** `clown-ai` 09 T64(무작위 자동 진행), 10 T65~T68.
