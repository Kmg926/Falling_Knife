# Grilling: 덱 개수 랜덤 + 잔고 10

> 2026-11-09. 계기: 광대 Ticket 09 직접 플레이 뒤 사용자 요청 "매 라운드마다 나오는 캔들의 종류와 수는 랜덤이어야 한다" → "개수도 랜덤으로 하되, 체력을 좀 많이 높이자. 10 정도로".
> 질문은 AI가 추천 답과 함께 묻고, 사용자가 채택·거절했다. 2라운드, Q1~Q12 **모두 채택**.

## 확인한 사실 (질문 전)
- **GDD 원문(PDF)**: 04장 시작 조건 "덱(하락 2, 상승 3) 공개 후 셔플" / 수치 표 "캔들 덱 2:3, 3:4, 4:4, 재장전 시 같은 구성", 의도 "하락 비율이 40%, 43%, 50%로 상승" / 재장전 "새 덱 공개 후 셔플" / 05장 "라운드마다 잔고와 덱 구성을 바꿔 난이도", 캔들 "라운드별 5, 7, 8장" / F01 "라운드별 구성(2:3, 3:4, 4:4), 개수 공개, 셔플, 하락 최소 1"
- 즉 GDD = **개수 고정·공개, 순서만 무작위**. 지금 코드도 같다(Fisher-Yates, 재장전 때 다시 섞음). 개수 랜덤은 GDD **변경**이다.
- 피해는 1 + 레버리지(최대 3) → 한 번에 최대 4. 잔고 10이면 한 라운드에 재장전이 여러 번 생긴다.
- 광대 AI는 남은 개수만 보므로 구성이 랜덤이어도 그대로 동작한다.

## 1라운드
| Q | 질문 | 추천 = 결정 | 이유 |
|---|---|---|---|
| Q1 | 잔고 | 3라운드 모두 10 | 사용자 요청. 라운드 차이는 덱 범위로. Inspector 값이라 나중 조정 쉬움 |
| Q2 | 개수 랜덤 방식 | 라운드 표 줄마다 총 장수 범위(최소~최대), 채울 때마다 총 장수와 하락 수(1 ~ 총−1)를 뽑음. 하락·상승 최소 1장씩 | GDD F01 "하락 최소 1" 계승, 뒤 라운드일수록 장수 많게 |
| Q3 | 재장전 | 채울 때마다(라운드 시작·재장전) 새로 뽑음, `덱 재장전 (하락N / 상승M)`으로 공개 | 개수가 랜덤이면 재장전도 일관되게 |
| Q4 | 개수 공개 | 유지: 구성은 보이고 순서만 숨김, `남은 캔들` 줄 유지 | GDD "공개 후 셔플". 플레이어·광대 같은 정보 |
| Q5 | 테스트용 고정 순서 | `Use Fixed Order` 켜면 문자열이 개수와 순서를 **둘 다** 정함. "구성과 다르다" 경고는 없앰 | 개수가 랜덤이면 비교 대상이 없음 |
| Q6 | 순서 | 광대 Ticket 10 먼저(지금 값으로 시연 표 계산됨) → 덱 랜덤은 `.scratch/random-deck/`에서 Spec → Ticket | 잔고 10이면 10의 시나리오를 다시 계산해야 함 |
