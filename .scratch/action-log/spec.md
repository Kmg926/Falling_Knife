## 변경·유지·확인

**변경:** 광대 생각 시간을 1초로 늘리고, 결과 문구 앞에 행동한 사람을 붙인다(`광대: 매도 → 하락! 플레이어 -1`). 화면 왼쪽 아래에 행동 로그(최근 8줄)를 보여 준다.

**유지 (이유):**
- U1 플레이어 공개 시간 0.5초 (내 행동은 내가 앎, 값은 한 번에 하나)
- U2 처리 순서·판정·광대 규칙 그대로 (이번 변경은 보여 주기만)
- U3 화면 가운데 상태 텍스트 줄 구성 그대로 (라운드·차례·선택·잔고·레버리지·남은 캔들·결과)
- U4 광대 생각 중 문구는 결과 줄 아래 덧붙임 (09 결정)
- U5 R은 끝난 화면에서만, 1라운드부터 (기존)

**확인 – 작동 (Play 모드·MCP, 행동 → 예상 결과):**
- C1 광대 차례: `광대 생각 중...`이 약 1초 → 공개 0.5초 (TMP 글자 변경 시각으로 측정)
- C2 결과 문구 4종에 행동한 사람: `플레이어: 보유 → 상승! 레버리지 1, 차례 유지` / `광대: 보유 → 하락! 광대 -2` / `광대: 매도 → 하락! 플레이어 -1` / `플레이어: 매도 → 상승! 변화 없음 (레버리지 0 그대로)`
- C3 재장전 줄은 결과 줄 아래 그대로 (`… / 덱 재장전 (하락N / 상승M)`)
- C4 로그: 행동마다 한 줄이 맨 아래에 붙는다. 재장전은 별도 줄
- C5 로그는 최근 8줄만 보인다(9번째 행동 뒤 맨 위 줄이 사라짐)
- C6 라운드 시작마다 `— 라운드 N —`, 클리어·최종 승리·패배 줄
- C7 라운드가 바뀌어도 로그 이어짐, R로 처음부터 → 로그가 `— 라운드 1 —`만 남음
- C8 로그가 화면 왼쪽 아래에 보이고 가운데 상태 텍스트와 겹치지 않는다 (캡처)
- C9 퇴행: `clown-ai` T65~T68 고정 순서 결과(판정·차례)는 같고 문구만 이름이 붙음 (잔고는 지금 10이므로 Play 중에만 2로 두고 확인)

**확인 – 경험 (직접 플레이):** 광대가 뭘 했는지 따라갈 수 있는가 / 1초가 답답하지 않은가 / 로그가 방해되지 않는가. 그다음 random-deck 12에서 미룬 판 길이·잔고 10 판단.

**확인 전:** 구현 전이라 전부 확인 전.

## Problem Statement

광대 턴이 0.5초 간격으로 지나가 플레이어가 광대가 무엇을 했는지 읽을 수 없다. 결과 문구에도 누가 행동했는지가 빠진 경우가 있고, 지나간 결과는 다시 볼 방법이 없다.

## Solution

광대 생각 시간을 GDD대로 1초로 늘리고, 결과 문구에 행동한 사람 이름을 붙인다. GameManager가 행동 기록 목록을 갖고, UIManager가 그 최근 8줄을 화면 왼쪽 아래 텍스트에 보여 준다.

## User Stories

1. 플레이어로서, 광대가 무엇을 했는지 읽을 시간이 있길 원한다.
2. 플레이어로서, 결과 문구만 보고 누가 행동했는지 알고 싶다.
3. 플레이어로서, 놓친 광대 행동을 왼쪽 아래 로그에서 다시 보고 싶다.
4. 플레이어로서, 재장전이 언제 있었는지 로그에서 보고 싶다.
5. 플레이어로서, 로그에서 라운드가 바뀐 지점을 알고 싶다.
6. 플레이어로서, 로그가 화면 가운데 정보를 가리지 않길 원한다.
7. 플레이어로서, R로 처음부터 하면 로그도 새로 시작하길 원한다.
8. 개발자로서, 광대 생각 시간과 보이는 로그 줄 수를 Inspector에서 바꾸고 싶다.
9. 개발자(구술 면담 대비)로서, 기록(상태)은 GameManager, 보여 주기는 UIManager로 나뉘어 있길 원한다.

## Implementation Decisions

- **Inspector 값:** GameManager `Clown Think Seconds` 0.5 → 1 (MCP로 변경, 코드 수정 없음).
- **GameManager — 행동한 사람:** `RevealRoutine`에서 판정 전에 `Participant actor = Current;`로 기억해 두고, 판정 뒤 `LastResult = $"{actor.Name}: {LastResult}";`. 판정 안에서 `PassTurn()`이 `Current`를 바꾸므로 **판정 전에** 기억해야 한다. 보유+상승 문구는 이름이 겹치지 않게 `보유 → 상승! 레버리지 N, 차례 유지`로.
- **GameManager — 로그(상태):** `List<string>` 기록과 읽기 전용 공개(`IReadOnlyList<string> Log`), `AddLog(string)`.
  - 행동 결과 줄(이름 포함), 재장전(`Reload()` 안), 라운드 시작(`StartRound()` 안 `— 라운드 N —`), 라운드 끝(클리어·최종 승리·패배 한 줄) 때 추가.
  - `Restart()`에서 지운 뒤 `StartRound()`.
  - (AI 제안 → 사용자 채택): GameManager는 **판 전체 기록을 모두** 갖고, "최근 몇 줄을 보일지"(`Log Lines` 8)는 **UIManager** Inspector 값으로 둔다. 이유: 줄 수는 보여 주기 문제이고, 전체 기록은 나중 결과 화면(GDD F07 "기록")에 쓸 수 있다. 한 판 기록은 수백 줄 이하라 부담 없음.
- **UIManager:** `logText`(TMP)와 `logLines`(8) 칸. `Refresh`에서 기록의 마지막 `logLines`줄을 줄바꿈으로 이어 표시.
- **Scene (MCP로 Editor에서):** Canvas 아래 `Log Text` (TextMeshPro - Text(UI)). 확인한 사실: Canvas는 Screen Space Overlay, Canvas Scaler는 Constant Pixel Size, 기존 `Status Text`는 가운데 기준 900×500, 글자 32, Galmuri11 SDF, 왼쪽 위 정렬.
  - (AI 제안 → 사용자 채택) 시작 값: 기준점·피벗 왼쪽 아래(0,0), 위치 (20, 20), 크기 560×220, Galmuri11 SDF, 글자 20, 왼쪽 아래 정렬, 회색(밝은 회색). 겹침은 캡처를 보고 조정(가운데 상태 텍스트가 아래로 내려오면 상태 텍스트 크기·위치도 같이 볼 수 있음).
  - UIManager의 `Log Text` 칸에 연결.
- **Ticket 순서 (Q7):** 13 속도 + 행동한 사람(C1~C3) → 14 로그(C4~C9).

## Testing Decisions

- **좋은 테스트:** 바깥 동작만. "고정 순서 + 입력 → 화면 글자(상태·로그)".
- **seam:** 기존(고정 순서 + 함수/키 → UI 텍스트) + 로그 텍스트. 시간은 TMP 글자 변경 이벤트 시각으로 측정(09에서 쓴 방법).
- **방법:** C1~C9 + MCP 캡처. 테스트 전 컴파일 시각 > 저장 시각. 퇴행은 Play 중에만 잔고 2로 바꿔 `clown-ai` 고정 순서 재사용(멈추면 10으로 돌아옴).
